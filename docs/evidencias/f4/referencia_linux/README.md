# Verificación de F4 en Linux

La evidencia corresponde a Python 3.13.5, en una `.venv` propia del proyecto, con
las seis dependencias directas de `requirements.txt` y el inventario efectivo en
`requirements_ejecucion.txt`. Se ejecutaron las once celdas del notebook original,
sin cambiar su código, en orden y dentro de un proceso IPython nuevo.

El entorno no permitió iniciar los sockets de un kernel Jupyter. Esta verificación
es secuencial mediante IPython y se distingue de Restart Kernel and Run All Cells
en VS Code. La ejecución en el equipo del proyecto utiliza el modo `proyecto`.

Las entradas F3 se reconstruyeron con las clases del código integrado en main
`4cd0c4c` y el original con SHA-256
`c8db6461c06c0de3efbdda6821d6d28c9aef7dff3c6fde64ac4fd3661e15b78a`.
`entradas_f3.json` identifica sus huellas reales. No se modificó el manifiesto
original Windows de F3 ni se atribuyeron sus huellas a estos CSV Linux.

Resultados: 27.633 anuncios elegibles; 2.080 principales; 5.039 en la ampliación;
42 pruebas correctas y 20 controles satisfactorios. Los seis barrios comparados
reúnen 514 anuncios. El mayor cambio absoluto de mediana en capacidades 2–6 es
3,35901994447243 %. El JSON conserva precisión completa; el informe redondea a
dos decimales para comunicar los resultados.

El notebook guardado contiene estas salidas y su contexto real. El manifiesto
registra las huellas de los módulos F4 y de las seis tablas y tres figuras públicas.
Los CSV por anuncio, el original y el entorno virtual permanecen fuera de Git.
